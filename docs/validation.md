# Проверка на тестовом сервере

Дата: 2026-11-09. Сервер: `178.237.199.16`, Ubuntu 24.04, 6 vCPU, 16 ГиБ RAM, доступен `/dev/kvm`. Внутри всех ВМ — Debian 13. Проверка проводилась на сервере, разрешённом пользователем; существующие публичные службы не переносились.

## Команды

```bash
.venv/bin/ansible-playbook --syntax-check site.yml
.venv/bin/ansible-lint --offline site.yml verify.yml destroy.yml rebuild.yml smoke-chaos.yml
.venv/bin/python -m unittest discover -s tests -v
.venv/bin/ansible-playbook site.yml
.venv/bin/ansible-playbook verify.yml
# Следующая команда вводит короткие реальные отказы в учебный стенд:
.venv/bin/ansible-playbook smoke-chaos.yml
```

`smoke-chaos.yml` проверяет netem, асимметрию, MTU, изоляцию ClickHouse от Keeper на узле, отключение моста и жёсткое выключение всех ВМ dc2. Использует таймеры 10–20 секунд. Не запускайте его на стенде с важной нагрузкой без согласования команды.

## Подтверждённые результаты

- Развёртывание `site.yml`: гипервизор + 11 гостевых ВМ, `failed=0`, `unreachable=0` на всех узлах.
- `verify.yml`: Debian 13, чистое завершение cloud-init, 121 направленная ICMP-проверка (включая self), разрешение всех FQDN на каждой ВМ, исходящий HTTPS, 4 диска по 5 ГиБ у каждого из 6 ClickHouse, SSH только по ключу, работающая serial-console и установленный аварийный пароль. Все проверки завершились успешно.
- На мостах ДЦ нет IPv4-адресов гипервизора; сеть между ДЦ проходит через ВМ-маршрутизатор.
- Шесть unit-тестов проверяют порядок восстановления, сохранение состояния при ошибке отката, защиту от старого таймера, повторный откат, ограничение времени и отсутствие воздействия при ошибке установки таймера.

- `smoke-chaos.yml`: все шесть сценариев завершились с `failed=0`, `unreachable=0`. Проверено реальное увеличение RTT между ДЦ (>50 мс при заданных 100 мс), блокирование ICMP при асимметрии, потеря больших DF-пакетов при MTU 576, установка/удаление правил изоляции Keeper (в том прогоне — ZooKeeper), состояние DOWN/UP моста и выключение/запуск трёх ВМ dc2. После автоматического отката SSH доступен ко всем ВМ.
- Перезагрузка `g2-router` через Ansible: `rebooted=true`, возвращение SSH за 40 секунд.

- Повторное полное применение `site.yml`: на гипервизоре и всех 11 ВМ `changed=0`, `failed=0`, `unreachable=0`. Идемпотентность подтверждена.

- Заключительный `verify.yml` после всех отказов, перезагрузки router и повторного применения: на всех узлах `changed=0`, `failed=0`, `unreachable=0`. Связность и гостевые настройки восстановлены.

## Файлы доказательств

- `reports/deploy.log` — вывод развёртывания.
- `reports/verify.log` — вывод проверки топологии, ОС, сети, дисков и доступа.
- `reports/chaos-smoke.log` — проверки воздействия и автоматического отката.
- `reports/idempotence.log` — повторный полный запуск без изменений.
- `reports/verify-after-chaos.log` — заключительная проверка после отказов и перезагрузки.
- `reports/reboot.log` — проверка перезагрузки маршрутизатора.
- `reports/runtime-host.txt`, `reports/runtime-router.txt`, `reports/runtime-guest.txt` — вывод команд, трассировка, диски, правила и журналы отката.
- `reports/lint.log`, `reports/syntax.log`, `reports/unit-tests.log` — локальные проверки.

## Границы проверки

Сервисы ClickHouse и ZooKeeper, RAID/LVM/XFS и генератор нагрузки не установлены этим проектом. Поэтому задержка запросов, кворум, репликация и сохранность данных здесь не измерялись. Для общей приёмки группы нужны роли остальных участников и полноценные отчёты по их метрикам.

Гипервизор не перезагружался: на нём есть сторонние службы. Полное удаление/пересоздание после передачи данных команде выполняется только явной командой `rebuild.yml -e confirm_destroy=itmo-g2`; разрушительная проверка всех дисков в этой сессии не выполнялась.

## Дополнение 2026-11-14: замена ZooKeeper на ClickHouse Keeper

По решению команды три ZooKeeper-ВМ `g2-zk1..3` удалены из IP-плана: это были
заглушки, а координацию ClickHouse выполняет ClickHouse Keeper на
`g2-ch1r1`, `g2-ch2r1`, `g2-ch3r1`. Актуальная лаба состоит из 8 ВМ:
router, 6 ClickHouse и load.

Исторические результаты выше относятся к прежней топологии из 11 ВМ и
сохранены как отчёт о том прогоне. Новые проверки ClickHouse/Keeper и
идемпотентность описаны в [clickhouse-validation.md](clickhouse-validation.md).
Для действующего стенда:

```bash
# Однократно удалить старые g2-zk1..3, если они ещё созданы:
.venv/bin/ansible-playbook cleanup-zookeeper.yml

# Пересоздать гостевые настройки и topology JSON без ZK:
.venv/bin/ansible-playbook site.yml
```

`destroy.yml` и `rebuild.yml` также удаляют legacy-имена `g2-zk*`.
