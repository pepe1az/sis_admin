# Журнал применения ИИ

Дата: 2026-11-09.

Запрос: изучить задание `Ravino/devops_education/itmo-sysadm-2026`, подготовить часть группы 2, связанную с ВМ и сетями, в `~/ucheba/sis_admin`. Пользователь разрешил использовать предоставленный сервер для проверки. Секрет из запроса не копировался в проект; существующий SSH-ключ обеспечил доступ.

Результат: роли Ansible для гипервизора, NoCloud/KVM, маршрутизатора и базовых гостевых настроек; IP-план; inventory для команды; скрипты сетевых отказов; плейбуки проверки и явного пересоздания; ранбуки.

Проверки: syntax-check, ansible-lint, unit-тесты отката, реальное развёртывание на выделенном пользователем тестовом сервере, сетевые и storage-проверки. Фактические результаты и ограничения записаны в `docs/validation.md`, вывод команд — в `reports/`.

Диагностика: первоначальный шаблон без видеоустройства приводил к повторному запуску GRUB. Проверка альтернативного CPU не решила проблему; добавление VGA позволило загрузить Debian. Исправление включено в шаблон, сохранён host-passthrough. При изменении XML выявлена необходимость сохранять UUID домена; роль читает существующий UUID и сохраняет его. Для новых ВМ UUID вычисляется детерминированно.

Автоматическая проверка безопасности отклонила предложение serial-консоли с автоматическим root-входом. Этот вариант не применялся. Реализован вход технического пользователя с отдельно сгенерированным паролем консоли; пароль хранится вне Git, SSH по паролю запрещён.

Изменения стенда в этой сессии выполнялись в рамках прямого разрешения пользователя на проверку. Для дальнейшего использования ИИ на общем стенде соблюдайте правило задания: агенту — чтение, изменения — под контролем человека. Участники должны понимать и самостоятельно защитить созданную конфигурацию.

## Публикация на GitHub

По прямому запросу пользователя создан публичный репозиторий
[pepe1az/sis_admin](https://github.com/pepe1az/sis_admin).
Авторизация подтверждена для `pepe1az`; для проекта настроены локальные
имя автора и GitHub noreply email. Исходный неопубликованный коммит исправлен,
чтобы не использовать рабочую учётную запись автора. HTTPS использует
отдельную авторизацию в `.local/gh`, исключённую из Git. Глобальная конфигурация
Git и существующие SSH-ключи не менялись. Перед публикацией выполнена проверка
отслеживаемых файлов на секреты.

## Замена ZooKeeper на ClickHouse Keeper, 2026-11-14

По прямому решению пользователя три ZooKeeper-ВМ `g2-zk1..3` удалены из
актуального IP-плана: это были заглушки, созданные до выбора реального
координатора. ClickHouse Keeper развёрнут на `g2-ch1r1`, `g2-ch2r1`,
`g2-ch3r1`; кластер 3 × 2 и схема данных не менялись.

Изменены `group_vars/all.yml`, `inventory/guests.generated.yml`, `README.md`,
IP-план, runbooks, сценарий 13, роль `guest` (убран ZK-firewall),
шаблон inventory (убрана группа `zookeeper`), `verify.yml` (адрес
cross-DC traceroute) и chaos-сценарий `isolate-zk` → `isolate-keeper`. Исторические отчёты в `reports/` не
переписывались; в `docs/validation.md` добавлено пояснение, что старые числа
относятся к топологии из 11 ВМ. Для действующего стенда добавлен
`cleanup-zookeeper.yml`, а `destroy.yml`/`rebuild.yml` учитывают legacy-имена.
