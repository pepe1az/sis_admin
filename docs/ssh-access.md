# SSH-доступ пяти участников

Публичные ключи: `keys/team/MacBook-Pro.pub`, `DeadlyM0uth.pub`, `Kirill.pub`,
`Danila.pub`, `Daniil.pub`. Первые два предоставлены пользователем, остальные
сгенерированы отдельно для каждого участника. RSA использует современные
подписи SSH; включение устаревшего алгоритма подписи ssh-rsa не требуется.

Каждый ключ даёт доступ к учётной записи подключения на гипервизоре
(в текущем inventory — `root`) и к `ansible` на гостях. На гостях у `ansible`
есть полный sudo без пароля. Имена Kirill/Danila/Daniil обозначают ключи,
а не новые гостевые учётные записи.

## Закрытые ключи

На исходном контроллере: `~/ucheba/sis_admin/.local/team-ssh/Kirill`,
`~/ucheba/sis_admin/.local/team-ssh/Danila`,
`~/ucheba/sis_admin/.local/team-ssh/Daniil`.
Каталог имеет режим 0700, закрытые ключи — 0600. Они без парольной фразы;
каждому участнику передают только его файл по защищённому каналу.
После получения можно задать парольную фразу: `ssh-keygen -p -f ~/.ssh/Danila`.
Весь `.local/` исключён из Git. В репозитории только публичные части.
Закрытые части двух предоставленных ключей остаются у их владельцев.

## Подключение после применения доступа

```bash
chmod 600 ~/.ssh/Danila
ssh-add ~/.ssh/Danila
ssh root@178.237.199.16
ssh -J root@178.237.199.16 ansible@10.22.1.10
# На госте:
sudo -i
```

Для новой схемы адреса гостей: `10.22.1.10`, `10.22.2.10`, `10.22.3.10`,
`10.22.1.30` (генератор), `172.30.2.2` (маршрутизатор).
Новые адреса пока только в коде; на действующем стенде старые ВМ.

## Применение

`site.yml` включает все пять ключей в cloud-init новых ВМ, а затем поддерживает
их через роль `ssh_access` на гипервизоре и гостях. Отдельный `access.yml`
обновляет только authorized_keys без изменения ВМ, дисков или ресурсов:

```bash
# Для уже развёрнутой новой схемы:
.venv/bin/ansible-playbook access.yml
# Для текущего старого стенда из 11 ВМ:
.venv/bin/ansible-playbook access.yml -e @profiles/legacy-11-vms.yml
```

Нужен существующий административный доступ для первого применения.
Роль ведёт отмеченный блок в authorized_keys и сохраняет ключи вне блока.
Удаление ключа из списка убирает его из этого блока; для полного отзыва доступа
также проверьте наличие копий вне блока и в cloud-init старых ВМ.
Ключи не включают SSH по паролю и не открывают root-вход на гостях.

Эти изменения подготовлены локально: по действующему указанию пользователя
сервер не менялся, playbook доступа на нём ещё не запускался.
